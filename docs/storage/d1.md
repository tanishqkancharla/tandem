# Cloudflare D1

`TandemServerD1Storage` syncs collections with existing D1 tables through a Cloudflare binding. It uses the [shared SQL mapping](../sql.md#shared-sql-mapping), binds query parameters, and commits each write batch atomically with D1's `batch()`.

The adapter is experimental: D1 preserves records, but mutation acknowledgements remain in memory. Read the [SQL limitations](../sql.md#sql-limitations) before choosing it.

## Connect a binding

Given the shared `tasks` schema from [Choosing storage](../sql.md#shared-sql-mapping), create a matching table with your migration tool:

```sql
CREATE TABLE tasks (
  id TEXT PRIMARY KEY,
  text TEXT NOT NULL,
  done INTEGER NOT NULL DEFAULT 0
);
```

Pass your existing D1 binding as `database`:

```ts
import { TandemServer } from "@tanishqkancharla/tandem-server"
import { TandemServerD1Storage } from "@tanishqkancharla/tandem-server/sql"
import { schema } from "./schema"

const storage = new TandemServerD1Storage({ schema, database: env.DB })
const server = new TandemServer({ schema, relations: {}, storage })
```

The adapter encodes booleans as `0`/`1`. For custom table or column names, compound IDs, or other values, use [custom SQL mappings](custom.md#custom-sql-mappings). Tandem does not create tables or run migrations.

## D1 and Durable Objects

D1 stores application records. A Durable Object can host `TandemServer` so its mutation queue and live connections share one owner. The D1 adapter itself only needs the database binding; it does not require a Durable Object or use that object's storage.

For the complete Worker, Durable Object, D1, and SSE setup, follow [Deploy on Cloudflare](../cloudflare.md).
